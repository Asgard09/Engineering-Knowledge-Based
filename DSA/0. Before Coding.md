# 0.1. Quy trình một buổi phỏng vấn DSA (UMPIRE)
## U - Understand (5 phút)
- Đọc kỹ đề, diễn đạt lại bằng lời cho interviewer.
- Hỏi 2-3 clarifying questions: edge cases, constraint, output
- Viết 1-2 ví dụ nhỏ kèm mong đợi
## M - Match (2 phút)
- Pattern ?
- Data structure ?
- Template ?
## P - Plan (5 phút)
- Bắt đầu bằng brute force – luôn đề cập
- Mô tả ý tưởng
- Big O
- Optimization
- Verify hướng giải
## I - Implement (15 phút)
- Code clean
- Comment các bước phức tạp
- Viết helper nếu cần
## R - Review (3 phút)
- Đọc lại code, soi bug
- Dry-run trên giấy
## E - Evaluate (2 phút)
- Phân tích lại big O
- Trao đổi về phương án tối ưu thêm nếu có
- Trả lời câu hỏi mở rộng: “Nếu input lớn?”
# 0.2. Cách trình bày code trên Whiteboard
## Golden Rule
1. Think out loud
2. Bắt đầu với ví dụ cụ thể
3. Code theo hướng top-down
4. Đặt tên biến rõ ràng
5. Đừng cố viết quá ngắn
## Khi bí ý tưởng
1. Brute force trước
2. Vẽ Tree, Graph, array ra giấy
3. Đơn giản hóa ví dụ
4. Xin gợi ý: “Đang lưỡng lự giữa BFS, DFS - and/chị có gợi ý nào không”
## Sau khi xong
1. Chạy thử bằng ví dụ chính
2. Kiểm tra edge cases
3. Phân tích Big O
4. Đề xuất tối ưu
# 0.3. Lưu ý
- Tránh tranh luận với Interviewer
- Đừng giả vờ biết. Nếu chưa nghe pattern này bao giờ: “Em chưa gặp pattern này trước đây. Hỏi về first principle”
- Cảm ơn ở cuối và xin feedback
